*** ROOT-CAUSE ANALYSIS: why does genuine routed generation show no speed
benefit despite ~17% layer-skipping (4/24 layers)? ***
Isolated via controlled ablation (LoRA on/off, router bypassed/active),
single query, GSM8K/0.5B:
  raw hf_model forward (no LoRA, no router): ~1725ms (floor)
  + LoRA (unfused, per-projection A@B matmuls):        +~720ms (+28%)
  + Router (manual Python loop, O(T) mean-pool/layer):  +~636ms (+27%)
  = routed total: ~2360-2540ms

FINDING: LoRA is NOT "interfering" with or offsetting layer-skipping's
benefit specifically -- both LoRA and the router add independent, large,
FIXED overhead (kernel-launch-bound, unfused, no KV-cache) that swamps the
modest ~17% compute saved by skipping 4/24 blocks. This is an
implementation-overhead confound, not a property of trained routing as a
paradigm. ALSO FIXED (root cause, not just a workaround): _forward_layers()
in BOTH gated_qwen.py and gated_llama.py never checked router.force_open
(dead code) -- now genuinely short-circuits per LayerRouter.forward()'s
intended behavior, verified via real forward-pass test (layers_run
3.0->4.0 confirmed). This was a LATENT bug in gated_llama.py too (never
exercised by TinyLlama's actual usage history -- evaluate.py used a
different, correct, bias-based mechanism throughout, confirmed via
exhaustive file audit -- so TinyLlama's PAPER RESULTS remain unaffected).

PAPER IMPLICATION: the audit's cost/speed comparison for LayerRoute should
explicitly discuss this as a real implementation-overhead limitation,
distinct from a fundamental critique of trained routing -- a fused,
KV-cached, production implementation could plausibly still realize real
speed gains from the same learned skip pattern.

*** MoD: TWO SEPARATE TRAINING BUGS FOUND AND FIXED ***
Bug 1 (convergence failure): original top-k-based token selection gave no
gradient signal for WHICH tokens should be selected (only weighted already-
selected tokens' output). Combined with zero-init ties, training never
converged: lm_loss=6.19 (ppl=486) after 3000 steps. FIX: replaced top-k
with a per-token STE threshold gate (same proven mechanism as LayerRoute's
LayerRouter, applied per-token). Verified every router receives non-zero
gradient post-fix (structural test). Retrained: lm_loss=1.85-1.89,
comparable to LayerRoute/LayerDrop's ~1.4-1.6 range.

Bug 2 (regularization target mismatch): gate_reg_weight regularized the
MEAN of raw soft_g (continuous [0,1] values). This can be satisfied by
every token clustering just ABOVE the 0.5 threshold (e.g. all soft_g~0.73)
-- average "looks correct" (close to target_capacity=0.75) while ZERO
tokens actually cross below threshold, giving skip_pct~0.1% despite a
seemingly-reasonable average. Confirmed via direct measurement (avg
soft_g=0.734, skip_pct=0.11%, weight_norm~0.26 -- genuinely non-degenerate
learned weights, just never pushed past the hard cutoff). Increasing
gate_reg_weight 5x had NO effect (confirms it wasn't a strength problem --
the regularization target itself was wrong). FIX: regularize the STE gate
(numerically equals the REAL hard 0/1 decision in the forward pass), not
raw soft_g. Retrained: skip_pct now 21.6-23.2%, genuinely close to the
25% target, loss unchanged/healthy (~1.86-1.89).

*** LayerRoute inference-time compute-skip FIX (real, verified speedup) ***
Root cause: _forward_layers() called layer() unconditionally regardless of
gate value -- "skipping" only ever discarded output, never avoided compute,
at training OR inference. FIX: added a real conditional skip
(if hard_g==0 and not self.training: continue) -- safe because STE's
gradient requirement only applies during training; inference needs no
gradient. Verified structurally (fewer real layer() calls, gate_values
list integrity preserved) AND via real measurement.

RESULT (GSM8K/0.5B, seed 2024, n=100, post-fix):
  routed: 28.89 ms/token | baseline: 31.24 ms/token | speedup: 1.08x
First genuine, non-zero speedup measured anywhere in this audit for
LayerRoute. Modest relative to the theoretical ~17% FLOP-reduction
estimate (4-8/24 layers typically skipped) -- explained by router overhead
(mean-pool+linear+sigmoid) being paid on EVERY layer regardless of skip
decision, diluting the layer-level savings. No retraining was needed --
existing checkpoint's learned gate decisions are unchanged; only whether
skipped layers' compute is genuinely avoided changed.

NOTE: accuracy findings (routed 0.16 vs baseline 0.33 at 0.5B, 0.01 vs
0.51 at 1.5B, degenerate/repetitive routed generations) are UNCHANGED by
